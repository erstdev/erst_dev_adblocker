# Глава 10. Глоссарий

## Зачем эта глава

В доке много терминов. Некоторые встречаются часто, некоторые — один раз, но важны. Если что-то забылось — ищи здесь. Все термины сгруппированы по темам, внутри — по алфавиту. В конце каждой статьи — отсылка к главе, где термин разбирается подробнее.

## Общие термины о расширениях

**Браузерное расширение.** Дополнение к браузеру, которое добавляет новые возможности. Набор файлов: манифест, скрипты, стили, ресурсы. Устанавливается через Chrome Web Store или через `Load unpacked` для разработки. См. главу 1.

**Content script.** JavaScript, который Chrome подсовывает в каждую открытую страницу. Видит DOM, но не видит переменные сайта. Запускается заново для каждой вкладки. Роль «рук» расширения. См. главы 2, 5.

**Manifest V2 (MV2).** Устаревшая модель расширений Chrome. Фон — постоянная HTML-страница, сеть — через код (`webRequest`), внешний код разрешён. С 2023 года постепенно отключается. См. главу 1.

**Manifest V3 (MV3).** Актуальная модель расширений Chrome. Фон — service worker (засыпает), сеть — через DNR (декларативные правила), внешний код запрещён. Наша модель. См. главу 1.

**Popup.** Маленькая HTML-страница, которая открывается при клике на иконку расширения. Живёт только пока открыта. Роль «лица» расширения. См. главы 2, 6.

**Service worker.** Фоновый JavaScript-скрипт расширения. Запускается Chrome'ом сам, живёт до 30 секунд без событий, потом засыпает. Обнуляет переменные при засыпании. Роль «мозга» расширения. См. главы 2, 4.

## Термины о манифесте

**`action`.** Блок в `manifest.json`, описывающий иконку расширения в тулбаре: всплывающую подсказку, popup. См. главу 3.

**`background`.** Блок в `manifest.json` с указанием пути к service worker и его типу (`"type": "module"`). См. главу 3.

**`content_scripts`.** Блок в `manifest.json` со списком файлов content script, URL-паттернов и временем запуска. См. главы 3, 5.

**`declarative_net_request`.** Блок в `manifest.json` с указанием ruleset'ов DNR. См. главы 3, 8.

**`host_permissions`.** Разрешения на работу с определёнными сайтами. У нас `<all_urls>` — на всех сайтах. См. главы 1, 3.

**`icons`.** Блок в `manifest.json` с путями к иконкам разных размеров (16, 32, 48, 128). См. главу 3.

**`manifest_version`.** Версия правил, по которым Chrome работает с расширением. У нас `3` (MV3). См. главы 1, 3.

**`permissions`.** Список прав расширения: доступ к API Chrome. У нас пять: `declarativeNetRequest`, `scripting`, `storage`, `webNavigation`, `tabs`. См. главу 3.

**`web_accessible_resources`.** Разрешения на доступ к внутренним файлам расширения через `fetch`. У нас — только `cosmetic-map.json`. См. главы 3, 4.

## Термины о DNR

**Action.** Поле в DNR-правиле, указывающее что делать с запросом: `block`, `allow`, `allowAllRequests`, `redirect`, `modifyHeaders`, `upgradeScheme`. У нас используются первые три. См. главы 8, 9.

**Condition.** Поле в DNR-правиле, указывающее при каких условиях срабатывает правило. Внутри — `urlFilter`, `resourceTypes`, `domainType`, `initiatorDomains` и т.д. См. главу 8.

**DNR (Declarative Net Request).** API Chrome для блокировки сетевых запросов через декларативные правила. Альтернатива старому `webRequest` из MV2. Chrome применяет правила сам, без участия кода расширения. См. главу 8.

**`domainType`.** Поле в condition DNR-правила: `"firstParty"` (тот же домен) или `"thirdParty"` (другой домен). См. главу 8.

**Динамические правила (dynamic rules).** DNR-правила, которые создаются и удаляются кодом через `updateDynamicRules`. Хранятся в профиле Chrome, переживают перезапуск. Лимит 5 000. У нас — только whitelist. См. главы 8, 9.

**`priority`.** Поле в DNR-правиле. Определяет, какое правило выигрывает при конфликте. У блокирующих 1, у allow 2, у `allowAllRequests` 100. См. главу 8.

**`resourceTypes`.** Поле в condition DNR-правила: какие типы запросов ловить. Возможные значения: `script`, `image`, `xmlhttprequest`, `sub_frame`, `main_frame`, `stylesheet`, `font`, `media`, `ping`, `websocket`, `other`. См. главу 8.

**Ruleset.** Набор статических DNR-правил из одного файла. У нас три: `ads_ruleset`, `exceptions_ruleset`, `manual_ruleset`. Управляются через `updateEnabledRulesets`. См. главу 8.

**Сессионные правила (session rules).** DNR-правила через `updateSessionRules`. Пропадают при перезапуске браузера. Лимит 5 000. У нас нет. См. главу 8.

**Статические правила (static rules).** DNR-правила из файлов, объявленных в манифесте. Суммарный лимит 30 000. У нас — основной набор блокировки. См. главу 8.

**`updateDynamicRules`.** API для создания, изменения и удаления динамических DNR-правил. См. главы 8, 9.

**`updateEnabledRulesets`.** API для включения и выключения статических ruleset'ов целиком. Используется при вкл/выкл расширения. См. главы 8, 9.

**`urlFilter`.** Поле в condition DNR-правила. Паттерн URL в синтаксисе, похожем на EasyList. См. главу 8.

## Термины о формате EasyList

**`!`** — комментарий. Строка игнорируется при конвертации. См. главу 8.

**`##`** — префикс косметического правила. После `##` идёт CSS-селектор, который надо скрыть. См. главу 8.

**`#@#`** — префикс исключения косметики. «Не скрывать это даже если есть правило». Пока не поддерживаем. См. главу 8.

**`$`** — префикс модификаторов. Идут после URL. Примеры: `$script`, `$image`, `$third-party`. См. главу 8.

**`@@`** — префикс сетевого исключения. `@@||site.com/allowed` — «не блокируй это». См. главу 8.

**`^`** — разделитель домена. Означает «конец домена или не буквенно-цифровой символ». `||ads.com^` соответствует `ads.com/`, `ads.com?`, но не `ads.computation`. См. главу 8.

**`||`** — префикс привязки к домену. `||doubleclick.net` соответствует всем поддоменам. См. главу 8.

**Cosmetic (косметические правила).** Правила EasyList для скрытия элементов на странице. Формат: `##.ad-banner` (общее) или `example.com##.ad-banner` (для конкретного домена). См. главу 8.

**Generic (общие).** Cosmetic-правила без привязки к домену. Работают на всех сайтах. Хранятся в `cosmetic.css`. См. главы 5, 8.

**Domain-specific (специфичные для домена).** Cosmetic-правила с привязкой к домену. Работают только на конкретном сайте. Хранятся в `cosmetic-map.json`. См. главы 5, 8.

## Термины о проекте

**Cosmetic map.** Файл `rules/cosmetic-map.json` — карта вида `{"домен": ["селектор1", "селектор2"]}`. Service worker отдаёт content script'ам только нужный кусок. См. главы 4, 8.

**Converter (конвертер).** Node.js-скрипт в `tools/`, который превращает EasyList в наш формат. Не входит в расширение, запускается вручную. См. главу 8.

**`cosmetic.css`.** Автогенерируемый файл с общими косметическими селекторами. ~14 000 правил. Вставляется на каждую страницу через `chrome.scripting.insertCSS`. См. главы 5, 8.

**`cosmetic-manual.css`.** Файл с ручными косметическими правилами. Не перезаписывается конвертером. Для случаев, не покрытых EasyList. См. главы 5, 8.

**`cosmetic-map.json`.** См. Cosmetic map.

**`exceptions.json`.** Автогенерируемый файл с allow-правилами DNR. ~500 правил. Приоритет выше блокирующих. См. главы 7, 8.

**`ads.json`.** Автогенерируемый файл с блокирующими DNR-правилами. ~28 000 правил. Основной набор блокировки. См. главы 7, 8.

**`manual.json`.** Файл с ручными DNR-правилами. Не перезаписывается конвертером. Для случаев, не покрытых EasyList. См. главу 8.

**Range (диапазон id).** Каждому набору DNR-правил выделен свой диапазон id, чтобы они не пересекались. Chrome использует единое пространство id. См. главу 8.

**Whitelist (белый список).** Список доменов, на которых блокировка не работает. Хранится в `chrome.storage.local`. Управляется через popup. См. главы 7, 9.

## Технические термины

**`chrome.runtime.sendMessage`.** Отправить сообщение из одной части расширения в другую. Кто слушает — тот получит. См. главу 2.

**`chrome.storage.local`.** Локальное хранилище расширения. Переживает перезапуск браузера. У нас хранит `enabled` и `whitelist`. См. главы 7, 9.

**`chrome.tabs.sendMessage`.** Отправить сообщение в конкретную вкладку (в content script). Требует `tabId`. См. главу 2.

**`chrome.webNavigation.onCommitted`.** Событие «браузер принял решение показать новую страницу». Срабатывает на каждый фрейм отдельно. Используется для вставки общего CSS. См. главу 4.

**Content script world (изолированный мир).** Среда, в которой работает content script. Видит DOM, но не видит переменные сайта. И наоборот. См. главы 2, 5.

**Frame, frameId.** Фрейм — часть вкладки. Главный фрейм (`frameId: 0`) — сама страница. Каждый `<iframe>` — отдельный фрейм с номером. См. главу 4.

**Manifest.** См. `manifest.json`.

**Mutex (мьютекс).** Защита от параллельного выполнения одной функции. У нас в `syncDnrState` через переменную `syncInFlight`. См. главу 9.

**MutationObserver.** API браузера для слежения за изменениями DOM. Используется в `observer.js` для скрытия динамически добавленной рекламы. См. главу 5.

**Race condition (состояние гонки).** Ситуация, когда два параллельных процесса зависят друг от друга, и результат зависит от порядка выполнения. У нас возникает при вызове `syncDnrState` из двух источников. Решается мьютексом и единственным источником вызовов. См. главу 9.

**SPA (Single Page Application).** Веб-приложение, которое меняет содержимое без перезагрузки страницы. Mail.ru, Dzen, YouTube — SPA. Требует специальной обработки навигации. См. главу 5.

**`pushState`, `popstate`, `hashchange`.** События и функции History API, через которые SPA меняют URL. Используются в `spa.js` для отслеживания навигации. См. главу 5.

**Shadow DOM.** Изолированная часть DOM внутри элемента. Стили и скрипты снаружи не проникают. Используется рекламными сетями (Яндекс.РСЯ) для защиты от блокировщиков. См. главу 1 и `docs/01-ARCHITECTURE.md`.
