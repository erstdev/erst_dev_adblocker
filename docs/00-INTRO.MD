# Глава 1. Введение

## Что это за проект

**erst_dev_adblocker** — это расширение для браузера, которое блокирует рекламу. Написан на чистом JavaScript, работает в Chrome и любом браузере на движке Chromium: Edge, Opera, Brave, Яндекс.Браузер, Vivaldi.

Расширение умеет:
- Блокировать рекламные запросы до того, как они уйдут в сеть.
- Прятать рекламные баннеры, которые всё-таки попали на страницу.
- Пропускать рекламу в видео (нажимать кнопку «Пропустить» за тебя).
- Включаться и выключаться одной кнопкой.
- Не работать на сайтах из белого списка (если сайт ломается из-за блокировки).

Это не форк uBlock Origin, не копия AdBlock Plus. Код написан с нуля, каждое решение задокументировано. Эта документация — часть проекта.

## Что такое расширение браузера

Браузер — это программа, которая умеет показывать веб-страницы. Расширение — это **дополнение** к браузеру, которое добавляет ему новые возможности: блокирует рекламу, переводит текст, ведёт заметки, меняет тему оформления.

Расширение — это набор файлов:
- `manifest.json` — паспорт, где описано, что расширение умеет и какие права ему нужны.
- JavaScript-файлы — код, который выполняется в разных «мирах» браузера (о мирах — в главе 2).
- CSS и HTML — оформление и разметка интерфейса, если он есть.

Браузер читает `manifest.json` и по нему решает: что загрузить, какие скрипты запустить, где показать иконку.

## Что такое блокировщик рекламы

Представь, что ты открыл новостной сайт. Браузер пошёл в интернет за ресурсами:
1. Запросил HTML — разметку страницы.
2. Получил CSS — стили.
3. Получил JavaScript — код сайта.
4. Получил картинки.
5. Получил **рекламу** — баннеры, видео, скрипты аналитики.

Реклама грузится **отдельными запросами** на рекламные домены. Условно: сам сайт `news.ru`, а реклама на нём — с `ads.evil-corp.com`.

**Блокировщик рекламы** перехватывает эти запросы и говорит браузеру: «`ads.evil-corp.com` не загружай». Реклама **не появляется**.

## Два уровня блокировки

Блокировать рекламу можно **на двух уровнях**. Оба нужны — они дополняют друг друга.

### Уровень 1. Сеть (network)

**Что:** не даём запросу уйти на рекламный сервер.

**Пример:** сайт пытается загрузить скрипт с `https://ads.evil-corp.com/banner.js`. Блокировщик режет запрос. Скрипт не загружается, рекламы нет.

**Плюс:** реклама не тратит трафик, не грузит процессор, не показывает ничего.

**Минус:** иногда реклама встраивается в сам сайт (не отдельным запросом), и её так не поймать.

### Уровень 2. Косметика (cosmetic)

**Что:** скрываем рекламные элементы, которые уже попали на страницу.

**Пример:** сайт встроил `<div class="ad-banner">...</div>` прямо в HTML. Сеть мы не можем это заблокировать (это часть страницы). Зато можем сказать браузеру: «элементы с классом `ad-banner` — не показывай». Через CSS:

```css
.ad-banner {
  display: none !important;
}
```

**Плюс:** работает там, где сеть не справилась — на нативной рекламе, встроенной в контент.

**Минус:** запрос всё равно ушёл, трафик потрачен. Мы просто не показываем результат.

В нашем блокировщике есть **оба уровня**. Сеть — через DNR (глава 8). Косметика — через CSS-правила (глава 5).

## Третий уровень — трюки

Есть реклама, которую **нельзя ни заблокировать, ни скрыть** — например, рекламные вставки **внутри видео** на YouTube или VK Видео.

Что происходит технически: сервер **склеивает** рекламный ролик и основной контент в **один видеофайл**. Браузер получает **один непрерывный поток**. Отрезать кусок невозможно — это как разрезать фильм на середине без монтажного стола.

Что мы делаем: **нажимаем кнопку «Пропустить» за тебя**. Пользователь обычно видит рекламу 5 секунд, потом появляется кнопка. Мы **нажимаем её автоматически** — как только она появилась. Реклама проигрывается 0-1 секунду вместо 30.

Это называется **авто-скип**. Реализован в `content/lib/auto-skip.js` (глава 5).

## Что значит Manifest V3

**Manifest** — это файл `manifest.json`. **V3** — третья версия **правил**, по которым Chrome работает с расширениями.

История: раньше (Manifest V2) расширения имели **очень много прав** — могли перехватывать **любой** сетевой запрос, видеть **всё**, что ты делаешь. Это было мощно, но **опасно**: вредоносное расширение могло украсть пароли, платёжные данные, переписку.

В **2023 году** Google выпустил **Manifest V3** — новую модель безопасности. Что изменилось:

- **Фоновые скрипты** больше не работают **вечно**. Они **засыпают** через 30 секунд без событий (разберём в главе 4).
- **Блокировка сети** больше не через код, а через **декларативные правила** в JSON — это DNR (глава 8).
- **Нельзя загружать внешний код** — только свои файлы.

Плюсы: безопаснее, экономнее по памяти.
Минусы: **меньше возможностей**. Многие блокировщики частично **потеряли функциональность** в MV3. Мы это компенсировали трюками (авто-скип, MutationObserver).

Всё, что мы делаем, — на **MV3**. Это то, что сейчас поддерживает Chrome. MV2 устарел.
